# mapping/

GT v2.5 → schema mapping. Every file here except `map_gt.py` and this README is regenerated by `validator/validate_spec.py`, so its notes live here instead of in the file (a rerun would overwrite in-file edits; the JSON/JSONL contract must not change).

| File | Purpose | Use case | Example |
|------|---------|----------|---------|
| `map_gt.py` | Mapper module (documented in its own docstring). | Imported by the validator to build envelopes. | `map_all()` maps all 532 GT rows. |
| `gold_outputs_all.jsonl` | Generated. One gold envelope per GT record (532 lines). | Reference outputs for the later copilot runtime and eval. | Line for `GT-LBS-DIR-011`: `"tools_expected": ["doc_search", "calculator"]`. |
| `gold_outputs_frozen.jsonl` | Generated. The 80 `frozen_core=true` envelopes. | The frozen eval set; must validate 80/80. Its SHA-256 is recorded in `eval/freeze-manifest.json`. | First line is `GT-LBS-DIR-011`, `"split": "eval"`, `"frozen_core": true`. |
| `gt-to-schema-mapping.md` | Generated. Table of which GT column fills which output field. | Human-readable mapping rules for reviewers. | `tools_expected` ← `expected_tools`, split on commas. |
| `mapping_issues.json` | Generated. Records with mapping-time warnings. | Spot GT rows that don't map cleanly. | Currently `[]` (0 issues). |

Regenerate: `.venv/bin/python3 validator/validate_spec.py` (repo) or add `--out-dir /tmp/x` to write elsewhere.
