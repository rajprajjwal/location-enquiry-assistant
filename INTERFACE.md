# Interpretation validation interface

Shared checks for the interpretation step. Another module owns
`copilot/interpret/` and `copilot/llm/client.py` and imports this package.
This package does not call a model, does not read provider APIs, and does
not modify the dataset validator.

Models are generated. Rule functions are written once and called from both
the Pydantic path and the post-check.

## Models (`copilot.models`)

Generated by `scripts/gen_models.py` with **datamodel-code-generator
0.96.0**. Do not hand-edit `copilot/models/generated/`.

| Class | Source |
| --- | --- |
| `QualificationDetails`, `UseCaseApi`, `MonthlyVolume` | `schemas/qualification_details.schema.json` |
| `Turn` | `contracts/interpretation/turn.schema.json` |
| `KnownFact` | `contracts/interpretation/known_fact.schema.json` |
| `InterpretationInput` | `contracts/interpretation/interpretation_input.schema.json` |
| `InterpretationOutput`, `Confidence`, `Trace` | `contracts/interpretation/interpretation_output.schema.json` (v0.1.0) |

`InterpretationOutput.qualification_details` is the v1.0.0 qualification
schema, referenced by its `$id`. The wrapper schemas live under
`contracts/interpretation/` rather than `schemas/`.
`validator/validate_spec.py` loads every `schemas/*.schema.json`, and the
design contract says the wrappers are not added there.

```python
from copilot.models import (
    InterpretationInput,
    InterpretationOutput,
    KnownFact,
    QualificationDetails,
    Turn,
)
```

The generated models enforce structure: types, enums, required keys,
string `minLength`, numeric bounds, and `extra='forbid'`. `uniqueItems`
stays a JSON Schema check inside `rules.py`. The generator would have to
emit a set to carry it, which drops vocabulary order.

Pydantic does not repeat the consistency rules. After a successful
structural parse, call the same functions the post-check uses:

```python
errors = validate_interpretation_output(model.model_dump(mode="json"))
```

`model_dump(mode="json")` may turn an integer `requests_per_month` into a
float. The qualification schema types that field as `number`, so both are
valid.

## Rules (`copilot.validation.rules`)

```python
from copilot.validation.rules import (
    REQUIRED_FIELDS,
    Vocab,
    canonical_provider,
    compute_missing_required_fields,
    load_vocab,
    normalize_enum,
    validate_interpretation_output,
    validate_qualification,
)
```

`load_vocab() -> Vocab` reads `vocab/controlled-vocabulary.json` and
attaches provider aliases. Attributes:

- `intents`, `sub_intents`, `apis`, `teams`, `providers` — tuples in file order
- `intent_to_sub_intents` — parent intent to its sub-intents, in file order
- `provider_aliases` — casefolded keys to the six canonical names

`provider_aliases` is not a key in the vocabulary file (`provider_merges`
is empty). The map is `mapping/map_gt.py` `PROVIDER_ALIASES` plus
`openstreetmap` → `OSM Nominatim` (`_PROVIDER_ALIAS_EXTRA`, also listed in
`mapping/gt-to-schema-mapping.md`). A unit test fails if those tables
diverge.

`normalize_enum(kind, value) -> str | None` with
`kind` one of `intent`, `sub_intent`, `api`, `team`. Casefold the string
and compare it to each vocabulary entry. Return the vocabulary spelling,
or `None` when the value is `None`, not a string, or not in the
vocabulary. No trim, no NFKC, no guessing. An unknown `kind` raises
`ValueError`.

`canonical_provider(value) -> str | None` strips the string, collapses
internal whitespace, casefolds it, and looks it up in `provider_aliases`.
Unknown strings, `None`, and non-strings return `None`.

`REQUIRED_FIELDS` is `qualification_required_fields` from the vocabulary
file, in that order: `use_case_api`, `region`, `monthly_volume`,
`current_provider`, `timeline`.

`compute_missing_required_fields(qual) -> list[str]` returns the required
fields whose value is `None`, in `REQUIRED_FIELDS` order. It reads values
only. It ignores any model-supplied `missing_required_fields` list,
including text that looks like an instruction. `""`, whitespace, `"n/a"`,
`"unknown"`, and `"none"` are present, not missing. A non-dict raises
`TypeError`.

`validate_qualification(qual) -> list[str]` and
`validate_interpretation_output(obj) -> list[str]` return `[]` when the
object is valid. They do not rewrite the object and they do not casefold
enums. The post-check normalises with `normalize_enum` and
`canonical_provider`, then validates.

## Errors

Each error is `JSON-Pointer-path: RULE_CODE: detail`.

The pointer is RFC 6901. The document root is an empty pointer, so a
root error starts with `: `. `~` and `/` inside a token are escaped as
`~0` and `~1`. For a `required` failure, the missing property name from
the jsonschema 4.26 message is appended so the pointer names the field a
repair prompt should fill.

Order:

1. JSON Schema errors, sorted by pointer, then rule code, then detail.
2. Consistency checks, in the fixed order below, not re-sorted into the
   schema errors.

`validate_qualification` consistency:

1. `MISSING_REQUIRED_FIELDS` at `/missing_required_fields` when the
   declared list is not exactly the computed list (order included).
2. `COMPLETE_FLAG` at `/complete` when `complete` is not `True` exactly
   when the computed list is empty.

`validate_interpretation_output` uses
`contracts/interpretation/interpretation_output.schema.json` with the
qualification schema registered under its `$id`. Nested qualification
schema errors already carry the `/qualification_details` prefix. It then
runs the two qualification consistency checks under that prefix, then:

3. `API_MISMATCH` at `/qualification_details/use_case_api/api` when
   `use_case_api.api` is not equal to top-level `api`.
4. `MISSING_FIELDS_MISMATCH` at `/missing_required_fields` when the
   top-level list is not equal to
   `qualification_details.missing_required_fields`.

Schema rule codes are the JSON Schema keyword: `TYPE`, `ENUM`,
`REQUIRED`, `ADDITIONAL_PROPERTIES`, `MIN_LENGTH`, `MINIMUM`, `MAXIMUM`,
`UNIQUE_ITEMS`, and the other keywords mapped in `rules.py`. A keyword
without a mapping becomes its `UPPER_SNAKE` form.

Details for consistency checks use JSON spellings (`true`, `false`,
`null`, quoted strings) and `<absent>` when the key is missing. Schema
details are the jsonschema 4.26 message, unchanged. Pin
`jsonschema==4.26.0`; those messages are part of the repair text.

## What this module does not do

The post-check owns these. They are defined, and they are not
re-implemented here:

- Case-folding and provider canonicalisation before validation. The
  helpers above are the implementation; `validate_*` does not apply them.
- Dropping a `sub_intent` that is not in `intent_to_sub_intents[intent]`
  to null and logging it. A globally valid sub-intent under the wrong
  parent is schema-valid. The map is on `Vocab.intent_to_sub_intents`.
- Grounding (evidence substring in a user turn or known fact).
- Stripping `<think>` blocks and parsing the first JSON object.
- Region alias canonicalisation and the §6.2 `norm()` used by the scorer
  (NFKC, null-likes, volume suffixes, substring match).
- History merge and "leave that open".

## UNKNOWN (not enforced)

`UNKNOWN_UNENFORCED` in `rules.py` records rules the spec and the
provider docs leave undefined. This module does not invent a threshold
for them.

- Coordinate semantics. No latitude, longitude, or geometry field is
  defined on the qualification object. Nothing here checks coordinates.
- Whether scoring null-likes should count as missing before
  `compute_missing_required_fields`. Only JSON null counts.
- Whether `abstain=true` requires a non-null `abstain_reason`, and
  whether `abstain=false` requires null.
- Whether `field_provenance` keys must be qualification field names.
  Values are the four tokens the contract names: `rule`, `model`,
  `history`, `state`.
- A minimum of 0 on trace counts. The envelope minimum on
  `approx_output_tokens` is not copied onto the trace. Negative integers
  are accepted. The type is integer because the contract shows integers
  from `ceil(chars/4)`.
- `trace.model` and `trace.prompt_version` as consts. The examples
  `Qwen/Qwen3-8B` and `interp-v1` are not required values. Any string,
  including empty, is accepted.
- A closed set or uniqueness constraint for `rule_model_disagreements`.
- Rejecting a whitespace-only query or turn `text` whose length is at
  least 1.

`confidence` values are inclusive on the written endpoints 0 and 1
(JSON Schema `minimum` / `maximum`). That reading is applied, not left
open.

## Regenerate models

```bash
python scripts/gen_models.py
```

Requires `datamodel-code-generator==0.96.0`. CI job
`interpretation-model-drift` runs that command and fails if
`copilot/models/generated` differs from the commit.
